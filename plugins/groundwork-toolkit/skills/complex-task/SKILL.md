# Complex Task

Big jobs fail one way: every part gets touched, no part gets finished. This
skill trades breadth for finished parts.

## Steps

1. Break the request into parts, six at most. Each part gets one sentence and
   a done-condition you could check without remembering the conversation.
   More than six means the parts are too small or the job is really two jobs;
   say so and split it.
2. Order the parts: what depends on what, and which are independent.
3. Work the parts:
   - If this session can delegate to the deep-planner, worker, and
     bulk-helper agents, use them: deep-planner first when the breakdown
     itself is the hard part, worker for each execution part, bulk-helper
     for mechanical volume (long summaries, repetitive edits). Hand each one
     everything it needs: the facts, the file paths, the done-condition.
     Run independent parts at the same time.
   - If this session cannot delegate, work the parts yourself, one at a
     time, in the same order, finishing each before starting the next.
4. Review every finished part against its done-condition before building on
   it. Redo what falls short; do not average it in.
5. Hand back one finished result, plus a short plain-language summary: what
   was done, any decision made along the way, anything still open.

## Rules

- The owner sees outcomes, never machinery. No mention of agents, helpers,
  models, or this skill in anything they read.
- The brain's safety rules bind every part, delegated or not: drafts only,
  never send, never move money, never sign.
- If a helper is unavailable or fails, do that part in the main conversation
  and keep going; the owner should not be able to tell the difference.
- If a part cannot be done at all, deliver the rest and say plainly which
  part is missing and what it needs. Never present a partial job as complete.
